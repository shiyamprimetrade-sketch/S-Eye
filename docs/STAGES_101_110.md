## API and compatibility

Existing `recognize` models and the 91-value legacy descriptor are unchanged.
`FeaturePipeline` additionally registers `geometry` (12 values) and `appearance`
(30). Selection/order/versions/dimensions produce a schema fingerprint. Packet
similarity requires identical schemas and explicitly balanced component weights;
no modular vector is silently passed to an old model.

New read-only JSON action `recognize_packet` takes `image`, `model`, optional
`calibration`, `top_k` (1..10) and `min_margin` (0..1). Models are separate
checksum-verified packet-prototype checkpoints; the trusted registry supplies
extractors, never a dynamic import from a request. It returns known-radius/margin
acceptance or unknown, training-label candidates, per-component distances, the
largest observed/prototype differences, source/model/schema hashes and optional
empirical validation support. Root grants and child-worker deadlines remain.

The calibration artifact is bound to one model and its exact declared validation
partition. It estimates empirical top-known-label correctness frequencies; it
never changes recognition labels, radius thresholds or returns a truth probability.
A fitted validation estimate is not representative calibration evidence.

Dataset revisions use `learning.versioning.snapshot(manifest, version, parent)`,
`save`, `verify` and `diff`. Standard schema-1 image manifests include dataset_id,
labels, annotation provenance, capture groups, paths, source SHA-256 and splits.
Bounded ingestion, canonical decoded-pixel identities and the existing conservative
near-duplicate/group split audit run before publication. Snapshots bind annotations,
splits, policy and parent revision; immutable saves refuse overwrite and version
ancestry must increase. Verification detects changed files. Dataset hashes include
original encoded file identity, so re-encoding is a different revision even if
pixels match. Declared label truth and genuinely independent captures cannot be
authenticated by hashing or the near-duplicate heuristic alone.

## Full regression and measured limitation

166 local tests pass, with focused tests and a distinct implementation commit for
each stage. CI runs every new experiment plus all historical checks. End-to-end
scoped CLI recognition, checkpoint loading and bound calibration also execute.
These are engineering checks, not a minimum recognition-success criterion.

The Stage 109 experiment fits 3 generated glyph categories on 9 training captures,
sets radii/calibration using 6 validation captures, and evaluates 6 shifted known
captures plus 4 unknown captures. Source-content hashes, IDs and declared groups
are distinct across partitions. The glyphs share a renderer and transformed
layouts: this is **correlated synthetic evidence**, not proof of independent
photographic or real-application generalization. It does not apply the Stage 110
near-duplicate audit to certify those synthetic test splits.

**Observed failure: 0/6 known captures accepted correctly; 4/4 unknown captures
rejected. All ten decisions were outside validation-derived radii.** The descriptors
include screen position/layout, so shift sensitivity is a plausible hypothesis,
not experimentally isolated causation. Class recognition reliability is therefore
not established. The full confusion matrix and per-class results are preserved.
No threshold was changed or selected on the test to manufacture a success.

The raw top-label correctness proxy Brier score is about 0.746674; validation-fit
empirical-support Brier is 0.2 on these ten generated tests. This improves that
proxy score while recognition labels remain unchanged and known recognition fails.
Neither value is a calibrated real-world truth-probability claim.

Stages 101–110 are complete only for the documented engineering contracts above.
The Stage 100–109 roadmap's broader representative recognition validation remains
unfulfilled. Do not interpret completion flags as measured expert programmer vision,
known-class reliability, OCR, code understanding or release readiness.
