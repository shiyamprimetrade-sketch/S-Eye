# Stages 181–190: local reliability

| Stage | Change and verification |
| --- | --- |

| 182 | Bound regular-file reads before allocation and at the read itself. Workspace reopening applies the remaining byte and pixel budgets per image. Memory page and bundle reads check payload totals before materializing results. |
| 183 | Resolve existing ancestors strictly, refuse cyclic and dangling links, and check workspace manifests against their workspace root. Allow new real output paths. |

| 185 | Create memory databases with owner-only POSIX mode from the first open. Use SQLite read-only and query-only modes for readers. Verify that a denied change leaves the database bytes intact. |
| 186 | Require standalone SQLite snapshots and reject sidecars during verification. A child process exits during an uncommitted write, and the committed record survives reopening and backup. |
| 187 | Sync restored database bytes before exclusive publication. Inject a sync failure and verify that the prior JSON remains intact, no restore appears, and temporary files are removed. |
| 188 | Use the shared path rules for config roots and bounded strict JSON for legacy memory imports. Check that rejected migrations preserve the original file, and compare declared pins with installed package metadata. |
| 189 | Run installed dependency and focused reliability checks in all four CI environments. Upload the structured report and let each matrix job finish independently when a peer fails. |
| 190 | Audit tracked and unignored files using NUL-delimited Git paths, reject missing or nonregular files, parse Python sources, and check Stage 84 preservation and release gates. |

Reproduce the focused controls after installing the development package:

```sh
python scripts/verify_hardening.py --output hardening-report.json
python -m unittest discover -s tests -v
python scripts/audit_source.py --output source-audit.json
python scripts/release_audit.py --output release-readiness.json
```

representative recognition, browser rendering and physical-device validation remain
open. Filesystem checks assume the caller controls the allowed workspace. S-Eye
