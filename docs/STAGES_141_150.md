## Measured results and negative results

The Stage 149 matrix has **27 generated sequences, 324 frames and 648 labeled
observations**. Its known box detections isolate association from segmentation.
Translations of the same nine fixture types are correlated stress cases.

| Method | TP | FP | FN | ID switches | Fragmentations |
| --- | ---: | ---: | ---: | ---: | ---: |
| Preserved legacy tracker | 618 | 36 | 30 | 9 | 9 |
| Opt-in conservative tracker | 591 | 36 | 57 | 12 | 21 |

Conservative abstention explicitly reports ambiguity but **does not improve the
aggregate tracking metrics**. Merged regions still cause missed observations and
identity switches. Abstentions count as false negatives; no difficult cases are
removed. Keep this mode opt-in. Stage 149 completes the executable engineering
harness; representative tracking validation remains open.

Stage 150 encodes three actual MPEG4 clips and runs local decoding, independent
segmentation and conservative tracking. Across **24 frames / 48 labeled
observations**, it measures **41 TP, 0 FP, 7 FN, 0 switches and 1 fragmentation**.
The source hashes remain unchanged. These are generated renderer oracles, not
captures of representative applications. The original Stage 139 overlap failures
are preserved rather than declared solved.

A resumed checkpoint produces exactly the same frame evidence and final state
as an uninterrupted sequence. Source mismatch, corruption, invalid recomputed
state, repeated publication, denied grants, dense candidates, excessive frames,
malformed media, noisy diagnostics and decoder deadlines have focused tests.
Checksums detect damage/mismatch; they do not authenticate callers or truth labels.

The allocation probe streams an 8 MiB file and observed roughly 2.1 MB peak traced
Python allocations. This measurement covers hashing only, not native FFmpeg RSS.
Stage 148 timings cover box association only, excluding decoding/segmentation;
Stage 150 reports probe, decode, analysis and tracking timings separately. No
Android/device or portable throughput claim is established. Timings and encoded
byte identities can vary by host and encoder.

## Interface and persistence

`interface_video` defaults to `tracking_mode="legacy"`; explicitly pass
`"conservative"` to request the new tracker. Existing `video` behavior remains
legacy. Both video actions require a video grant and an allowed read root.
`interface_video` is limited to 1..4 FPS and 1..6 seconds. Coordinates refer to
actual decoded frames scaled to fit 300×400, not original video pixels. Times are
resampling-grid times, never claimed to be original presentation timestamps.

The installed `seye-workflow` request contract supports `action="track_sequence"`
with `source_sha256` and explicit `samples`. Each sample supplies `timestamp`,
`source_size`, `detections` and optional boolean `discontinuity`. Example request:

```json
{
  "schema_version": 1,
  "request_id": "sample-observation",
  "action": "track_sequence",
  "source_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "config": {"session_id": "example-session"},
  "samples": [
    {"timestamp": 0, "source_size": [100, 80], "detections": [{"class": "region", "box": [10, 10, 30, 30]}]},
    {"timestamp": 0.5, "source_size": [100, 80], "detections": [{"class": "region", "box": [12, 10, 32, 30]}]}
  ]
}
```

The repeated `a` digest is an example caller assertion, not a hash of real media.
For real data supply the actual source digest. This boxed-data API cannot verify
that caller-provided detections or source assertions are true. Decoded-video mode
binds its observations to the bytes it actually snapshots and decodes.

Optional `checkpoint` reads existing state; `output_checkpoint` exclusively writes
new state. Both require explicit persistence (`--memory`) plus corresponding
read/write roots, in addition to `--video`. Config overrides on resume are refused.
Resume requires the same source digest and later sample times; a resumed chunk
returns no standalone full-history summary. Summarize the full preserved timeline
for complete history. Snapshots continue a session; copying one intentionally
forks that session rather than minting independently verified object identities.

## Bounds and remaining limits

- Per session: 300 frames, 64 active tracks, 64 detections per frame; sampling
  times are finite, at most 1e9 seconds and separated by at least one microsecond.
- Per sequence request: 1 MiB encoded input, 4096 supplied detections, 16384
  candidate-evidence edges and 16 MiB returned temporal evidence.
- Encoded input: 128 MiB with chunked reads and a private hashed snapshot; original
  source is checked again after processing. No whole-video Python read is used.
- Probe/decode deadlines: 10/60 seconds. Diagnostics are monitored at 64 KiB;
  decoded PNG output is monitored at 128 MiB / 300 frames. FFmpeg gets one decoder
  and filter thread and a 64 MiB **per-allocation** limit. Polling can detect an
  overshoot; these checks do not guarantee a total native RSS ceiling or sandbox.
- A caller-declared discontinuity resets associations without reusing IDs. No
  automatic scene-cut, scroll/camera registration or persistent semantic identity
  is inferred. Covered/unobserved objects are hypotheses, not proven occlusions.
- Native decoder process isolation, representative videos, UI text/OCR and expert
  programmer-level understanding remain unfinished. Release readiness stays false.
