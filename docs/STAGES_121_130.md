## Memory contract and S integration

New `observe_interface` memory writes retain a modular packet (default `shape`,
optional `memory_components`) and canonical decoded-pixel identity, in addition to
structured visual evidence. The source hash is rechecked before persistence so
changed files cannot silently bind different features to an observation. Previously
stored records remain untouched; absent/invalid historical hash declarations stay
unknown, with warnings and original provenance preserved. New trained observations
also record pixel identity. Session occurrence keys are explicit, not inferred time.

All new JSON actions require explicit memory capability and filesystem grants:

| Action | Effect |
| --- | --- |
| `memory_index_build` | Explicitly rebuild derived packet indexes; write grant required |
| `memory_packet_query` | Read-only query from `image` and matching `components`; optional `limit`, `exclude_sources`, `maximum_distance` |
| `memory_history_link` | Explicit caller link using entity, observation_id, session, event_index and reason; write required |
| `memory_history` | Read caller-linked events; no inferred object identity |
| `memory_inspect`, `memory_provenance`, `memory_duplicates` | Read identity, uncertainty and duplicate evidence |
| `memory_compare`, `memory_scene_inventory` | Read stored source-grid visual scene hypotheses |
| `memory_bundle_export` | Read source memory and exclusively write a verified bundle |
| `memory_bundle_restore` | Recover a verified bundle to a new writable database path |
| `memory_retention_plan` | Preview a policy using maximum and protected observation IDs |
| `memory_retention_apply` | Explicitly apply the complete unchanged snapshot-bound plan; write required |

The compatibility-default template/recognition paths and old observation storage
remain supported. Existing legacy `Memory.export`/`import_file` are observation-only;
the new bundle includes caller-history links. Derived indexes are omitted and must
be rebuilt after restore. Use the new retention plan/apply API for dependent-history
cleanup; legacy direct retention retains its original observation-only behavior.
No host capture, mouse, keyboard, external messages or main-S changes are introduced.

## Index correctness and bounds

The index uses a SQL schema key and persistent balanced KD trees over component-
balanced projected vectors. Default distance equals the modular component-balanced
RMS metric. Source observations remain authoritative. Query requires a fresh source
inventory snapshot and cache checksum, verifies returned candidates against source
packets, and excludes incompatible schemas. New observations or retention invalidate
the cache; read-only queries do not silently rebuild it. Explicit source hashes can
be excluded. A maximum distance is an optional caller policy, not calibrated truth.
Even limit=1 searches enough neighbors to report a tied top distance.

Budgets: 10,000 observations, one million indexed scalar values, 32 MiB per encoded
tree, 100 returned matches and 100 excluded source digests. High dimensions/ties
may degrade pruning. Integrity verification, snapshot scans and JSON loading remain
linear, and trees are derived integrity-checked caches, not authenticated data.
No sublinear end-to-end latency or malicious-recomputed-cache authenticity guarantee
is claimed. Checksums are corruption detection, not signatures or label verification.

## Recovery and retention

The portable bundle is bounded to 10,000 observations/events and 16 MiB. Its
checksum, observation order and every event reference are validated before a new
database is published exclusively. Existing destinations are never overwritten.
Recovery means restore from a valid bundle to a new path; arbitrary physical damage
is not repaired in place. Old sources/checkpoints are preserved. A tampered/rehashed
bundle with bad event references fails without publishing a destination.

Retention previews are snapshot-bound. Apply takes a write lock, rechecks the plan,
protects pinned observations, deletes dependent history events in the same transaction
and invalidates indexes. Stale plans fail without deleting observations. Corrupt
history fails closed rather than being hidden by cleanup. Caller-asserted target
links and session-local ordering do not establish cross-session semantic identity.

## Reproduce and measured evidence

```bash
python scripts/benchmark_stage121_130.py --stage 123 --output /absolute/new/index-query.json
python scripts/benchmark_stage121_130.py --stage 129 --output /absolute/new/retrieval-quality.json
python -m unittest discover -s tests -q
```

Each stage 121..130 accepts its own number and writes a separate report. There is
one implementation commit and focused test transcript per stage; 210 local tests
pass in the final regression. Tests cover cache freshness/corruption, exact-search
agreement, read-only bytes, source exclusions, duplicate distinctions, history,
rollback/recovery, missing legacy identities, scoped grants and scene ambiguity.
CI runs every experiment and the historical suite; exact-head proof is separate.

- 64-vector numeric fixture: top three match exhaustive search, using 7 distance
  evaluations versus 64. This is a distance-computation result, not measured wall-
  time acceleration of the complete verified memory pipeline.
- Two PNG encodings of the same generated pixels form one pixel/feature group and
  zero encoded-file duplicate groups. No record is automatically deleted.
- Recovery fixture restores two observations and one caller-history event; retention
  keeps a pinned observation and transactionally removes a deleted source's link.
- Gallery: six generated glyph captures. Six new-position known queries all retrieve
  the correct oracle category at top one/within top three; four generated unknown
  queries have no matches under the fixed inherited 0.015 cutoff. All six known
  queries have equal-distance ties, so unique-object identity is unresolved. Oracle
  labels score results but never rank them. The renderer is shared with prior
  experiments: this is not representative application retrieval validation.
- Scene fixture preserves two nested visual hypotheses and geometric containment,
  while semantic object count, labels and clickability remain unknown. A whole-frame
  classifier label is never converted into an invented scene object inventory.

## Stop

Stages 121–130 complete these bounded engineering contracts, not general semantic
memory or expert programmer vision. OCR, registration, semantic object identity,
representative retrieval quality and v1.0 release criteria remain unfinished.
Stop at 130; wait for Continue before 131–140, beginning with evidence-grounded
spatial relationships and scene comparison. Preserve the old baselines and explicit
uncertainty; do not turn proximity, feature equality or caller history links into
proven real-world identity. Human review does not block ordinary engineering.

The final end-to-end child-worker CLI smoke runs seven scoped actions: observe and
persist an interface, build index, query, assert a caller history link, export,
restore to a fresh path and inspect the recovered scene inventory. It passed with
one stored visual hypothesis and null semantic count. New integration tests verify
read-only database bytes and fail closed on a rehashed bundle with invalid history.
Legacy null/non-digest metadata is preserved as declared provenance and exposed as
unknown identity with warnings, rather than being promoted to a valid hash.
